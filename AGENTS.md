# Redrooms — инструкции для AI-разработчиков

## Проект и текущий этап

Это реальный Telegram Mini App «Красная комната», игра v06. GitHub: https://github.com/ladohinpy/redrooms.
Цель текущего этапа (ЭТАП 0): **разместить существующую автономную игру на Telegram Serverless как статический Mini App.**

На этапе 0 ЗАПРЕЩЕНО добавлять проверку подписки, серверную авторизацию, обработчики Telegram-обновлений, сохранение очков на сервере, SQLite-таблицы, AI-модели или новые игровые режимы. Всё перечисленное — только после отдельной задачи и одобрения владельца.

## Что сейчас работает

- `public/index.html` — самодостаточная собранная HTML v06, содержит игровую сцену, стили, каталог и встроенный JavaScript.
- Игра: 201 кассета, 4 стола режиссёров, сортировка кассет, подсчёт очков и сохранение локального прогресса. Эти правила и внешний вид сохранять.
- Адаптация к телефонам, fullscreen по действию игрока, пауза и управление двумя пальцами — сохранять.
- `tgcloud.jsonc` — конфиг публикации статических файлов из `public/`.
- `tgcloud/schema.js` — пустой серверный модуль. Нет активных handlers/endpoints и таблиц.
- `.github/workflows/check.yml` — проверка PR.
- `.github/workflows/publish.yml` — РУЧНАЯ публикация ТОЛЬКО `public/`.

## Правила работы

1. Сначала читай `README.md` и документацию `docs/archive-v06/DEVELOPER.md`, `docs/archive-v06/QA.md`.
2. Архивные документы описывают старый вариант с отдельным сервером. Это исторический контекст, **не команда реализовывать его**. Текущая платформа — Telegram Serverless.
3. Сохраняй игровую механику и оригинальный набор кассет. Не переписывай Three.js и не заменяй игру макетом.
4. Делай изменения в отдельной ветке и создавай Pull Request с описанием эффекта, проверок и возможных рисков.
5. Выполняй `npm run check` до PR. Для критических правок нужны ещё и реальные проверки на мобильных устройствах.
6. НИКОГДА не коммить токены BotFather, `TGCLOUD_TOKEN`, `.tgcloud/`, `.env`, пользовательские данные или другие секреты.
7. Не вызывай `tgcloud push`, `tgcloud migrate`, `tgcloud webhook sync` и не меняй настройки бота без отдельного разрешения. Публикация только вручную через workflow владельца.
8. Разрешённый текущий deploy — `tgcloud push public/` через GitHub Actions. Полный `tgcloud push` может удалить отсутствующие в репозитории серверные модули бота: для него требуется отдельная проверка удалений.
9. Никогда не создавать Telegram message handler с автоответом-«эхом» как побочный эффект scaffolding.
10. Не вводить внешние AI API и не добавлять платные сервисы.

## Официальная платформа

- https://core.telegram.org/bots/serverless
- CLI: `@tgcloud/cli` (Node.js >= 18), нужен токен `TGCLOUD_TOKEN` в GitHub Actions.
- Static hosting: `tgcloud.jsonc -> static.source = public`.
- Telegram публикует Mini App по адресу `https://app<app_id>.tgcloud.ai/`; фактический адрес выводится при публикации.
- Для будущих функций: `tgcloud/endpoints/*.js`, `tgcloud/handlers/*.js`, `tgcloud/lib/*.js`, `tgcloud/schema.js`. Подключать только по отдельной задаче.
- Вся серверная логика пишется на JS с SDK `sdk`; никаких сторонних npm-пакетов внутри Serverless runtime.
