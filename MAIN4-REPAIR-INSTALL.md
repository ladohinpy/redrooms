# RedRooms — восстановление согласованной сборки main

Патч: **MAIN4 ASSEMBLY REPAIR 1**, 28 октября 2026 года.
Основа: предоставленный `redrooms-main (4).zip`, коммит
`1566f8c7ff0f89b8902340d7a25d555574282ed0`.

## Что исправлено

В объединённом main присутствовал `admin-test-isolation-1`, рассчитанный на
`ATTEMPT STATE 1`, но отсутствовала клиентская часть последнего: исходник v12,
запись в реестрах сборок, готовая игра и её runtime, исправленный клиент попыток
и выбор этой сборки. Серверный код изоляции администраторов уже был новым.

Проверка исходного архива: **398 тестов, 384 прошли, 14 не прошли**. Ошибки
`assert.ok(fix)` и `ENOENT: src/rr-game-v12.html` воспроизведены, вместе с проверками
восстановления старой попытки. Это не ошибка Telegram, миграции или ключа.

Патч добавляет недостающие части v12 из ранее выданного `redrooms-attempt-state-fix.zip`
и согласует маршрутизацию/генерируемые файлы. Последний серверный код и интерфейс
изоляции администраторов из вашего main сохранены побайтно. Старые патчи отдельно
накладывать не нужно: их повторное применение может перезаписать новые изменения.

## Установка через GitHub

1. Создайте ветку **`fix/main-assembly` от текущего main**.
2. Распакуйте `redrooms-main4-assembly-fix.zip` и перенесите его содержимое
   в корень проекта, сохранив пути. Замените совпадающие файлы; остальные не удаляйте.
   Не загружайте ZIP как один файл и не добавляйте дополнительную вложенную папку.
3. В изменениях должны присутствовать **новый `src/rr-game-v12.html`**, обновления
   `config/rr-built-games.json` и `config/rr-game-builds.json`, каталог
   `public/games/v12-attempt-state/`, `public/rr/runtime/9421c987412827b3/`
   и остальные файлы из `MAIN4-REPAIR-MANIFEST.json`.
4. Дождитесь проверок Pull Request и объедините его с main.
5. Запустите **новый Run workflow → Publish Red Room — Admin & Releases → main → PUBLISH**.
   Не повторяйте старый неудачный запуск: нужен коммит с исправлением.
6. После успешной публикации полностью закройте старую Mini App и откройте её заново.

Прежние `RR_ADMIN_IDS`, `RR_STAGE_BOT_USERNAME` и `TGCLOUD_TOKEN` остаются.
Workflow не заменяется. Штатная отправка JSON-бэкапа перед обновлением сохраняется.
Не очищайте базу или localStorage, не применяйте `--force` и не отключайте тесты.

## Контрольные проверки

- Оба аккаунта из `RR_ADMIN_IDS` видят кнопку «Админка» на первом экране.
- Администратор может повторять тестовые прохождения без лимита двух попыток.
- Тесты администраторов не увеличивают статистику участников; их историю можно
  увидеть только через существующий фильтр «Показать проверки администраторов».
- Обычный игрок может использовать две зачётные попытки активного конкурса,
  но не третью. Само открытие приложения не расходует попытку.
- Закрытая старая попытка больше не зацикливает вход, неподтверждённый финиш
  не удаляется, потерянное подтверждение восстанавливает прежнюю запись.

## Что не менялось

Дизайн, административная авторизация, проверка подписки, текущие формы админки,
схема и слой хранения базы, бэкапы, workflow, правила +100/−75 и конкурсный лимит.
Существующий README не заменяется. Все шесть прежних игровых сборок и связанные
с ними исходники/runtime/frozen-ресурсы сохранены побайтно.

Текущая выбранная игра, каталоги, попытки и официальные итоги не сбрасываются.
Исправленный renderer подключается к прежним логическим ID и ключам сохранений.
Новая схема/миграция не добавляется; обычный workflow проверит состояние БД как раньше.

В `.gitignore` восстановлены стандартные исключения локальной конфигурации,
которые уже добавляет `rr-prepare.cjs`. Сгенерированный файл с ID администраторов
`tgcloud/lib/rr/config.js` в ZIP не включён: он создаётся из переменных при сборке.
