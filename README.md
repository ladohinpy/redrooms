# Красная комната — админка, каталоги и релизы

Ветка обновления: `feature/admin-releases` · версия функции: `admin-releases-v1`.
Проект: https://github.com/ladohinpy/redrooms

> Для получателя ZIP: это пакет обновления существующего репозитория, а не самостоятельная копия `main`.
> Начните со [START-HERE.md](START-HERE.md). Исходную игру сборщик берёт из вашего checkout;
> в пакет не подставлена другая игра. Секретов и реальных Telegram ID администраторов в архиве нет.

## Что делает приложение

Существующая v06 — 3D-комната с кассетами, столами режиссёров, сортировкой, очками, штрафами
и локальным прогрессом. Её исходник, встроенная графическая библиотека, управление, мобильная
оболочка и проверка подписки сохраняются из актуальной рабочей копии.
Для исходной сборки проекта ожидаются 201 кассета и четыре стола; количество не зашито в новой
админке. При сборке выводится фактический размер каталога, извлечённого из игры.

Новые функции не требуют отдельного Python-сервера, n8n или SaleBot: серверные модули используют
Telegram Serverless, хранилище — его SQLite. Реальную совместимость с облачным SDK проверяет
отдельный smoke-тест в процедуре публикации; локальные тесты не заменяют эту проверку.

### Возможности администраторов

| Раздел | Реализовано |
|---|---|
| Доступ | Ровно два заданных Telegram ID; одинаковые права Павла и Виталия; проверка на каждом серверном запросе |
| Каталоги | Создание черновика, копирование существующей версии, явное сохранение, отдельная публикация |
| Режиссёры | Добавление, переименование, включение/выключение; удаление после переноса/удаления фильмов |
| Фильмы | Добавление, название, оригинальное название, год, перенос между режиссёрами, удаление из черновика |
| Модерация | «На проверке», «Одобрен», «Исключён»; массовое одобрение/исключение найденных фильмов |
| Поиск | По названию, оригинальному названию, ID, году, режиссёру; фильтры; 25 карточек на странице |
| Импорт | JSON, CSV и TSV в UTF-8; до 1 МиБ; предварительная проверка; импорт не публикует данные |
| Экспорт | Каталог в JSON/CSV; резервный JSON-снимок состояния через админку |
| Релизы | Связка конкретной сборки кода и опубликованной версии каталога; административный предпросмотр |
| Публикация релиза | Отдельно от публикации каталога и отдельно от выбора основной игры |
| Основная игра | Кнопка «Сделать основным»: новый обычный запуск получает выбранный релиз без деплоя |
| Другие версии | `release`, `game`, Telegram `startapp`; старые опубликованные релизы продолжают открываться |
| История | Последние 200 действий с проверенным Telegram ID автора; переключение и запись истории атомарны |
| Конфликты | Устаревшее сохранение отклоняется; несохранённые данные остаются в редакторе |
| Интерфейс | Русскоязычная адаптивная админка; ссылка из игры для администраторов |

**Не реализовано:** новые механики «Оскары»/голосование, рейтинги, серверные игровые сессии,
античит, загрузка произвольного JS из админки, сторонние кино-API, загрузка постеров,
отдельные роли «редактор/утверждающий», автосохранение, автоматический полный restore из backup.
В текущем пакете одна настоящая кодовая версия — ваша v06. Псевдоним `v1` ведёт к ней.
Вторая версия кода появится только после добавления и публикации настоящего нового исходника.

## Вход и безопасность

Сервер берёт ID исключительно из `ctx.initData.user.id`, проверенного Telegram.
`userId`, `isAdmin`, username и параметры ссылки, переданные клиентом, прав не дают.
`initDataUnsafe` не используется для авторизации. Даже прямой вызов административного endpoint
обычным пользователем должен завершаться отказом.

До production-сборки нужно задать ровно два положительных числовых ID:

- `RR_ADMIN_IDS` — переменная окружения / GitHub Repository variable: два ID через запятую;
- либо локальный `config/rr-admins.local.json` по примеру `config/rr-admins.example.json`.

Реальные числа здесь намеренно не указаны. Пустой список закрывает админку всем;
`--production` с пустым или неправильным списком останавливает сборку.
Allowlist генерируется только в `tgcloud/lib/rr/config.js`, не в клиентском коде.

Исходные `tgcloud/endpoints/checkAccess.js` и `tgcloud/lib/subscription.js` остаются механизмом
проверки подписки. Сейчас проект использует тестовый канал `@redrooms_stage`; админка не
переключает канал. Для запуска игры проверка подписки обязательна и для администраторов.
Сам интерфейс управления и его данные не требуют подписки, но требуют административного ID.

HTML, JavaScript и названия статических файлов публичны. Это не DRM. Браузерную игру можно
модифицировать на своём устройстве; UI-проверка не является античитом.
Черновые релизы и каталоги защищаются на сервере. Режим «по ссылке» — **не приватный**.
Импортированные строки выводятся как текст, не исполняются как HTML. Токенов в URL нет.

## Работа с каталогом

1. Выберите опубликованный каталог и нажмите «Создать копию», либо создайте пустой черновик.
2. Отредактируйте режиссёров и фильмы или загрузите JSON/CSV. Импорт заменяет только локальное
   содержимое редактора после подтверждения; все импортированные фильмы получают `pending`.
3. Одобрите или исключите фильмы. Можно отфильтровать строки и применить действие ко всем найденным.
4. Нажмите «Сохранить черновик». До этого момента изменения есть только в текущей вкладке.
5. Нажмите «Опубликовать каталог». Сохранённая версия становится неизменяемой.
6. В разделе «Релизы» создайте связку с кодом игры и этой коллекцией.

Сохранение и публикация — разные действия. Закрытие Telegram может уничтожить несохранённый
черновик; `beforeunload` не гарантирован на телефонах. Сохраняйте изменения перед выходом.
При сетевом таймауте результат записи может быть неизвестен: сначала обновите состояние,
не повторяйте создание/публикацию вслепую. При конфликте можно экспортировать несохранённый JSON,
затем загрузить актуальное состояние и вручную согласовать изменения.

Дубликаты ID — ошибка. Совпадение названия и года — предупреждение для ручной проверки.
Один фильм в одном наборе привязан к одному режиссёру: это формат ответа существующей игры,
а не энциклопедическая модель совместной режиссуры.
При публикации отключённые режиссёры и исключённые фильмы не попадают в игровую коллекцию.
Включённый режиссёр с `pending` блокирует публикацию. Пустые столы отбрасываются.

### Формат JSON

```json
{
  "schemaVersion": 1,
  "id": "my-collection",
  "name": "Новая коллекция",
  "directors": [
    {
      "id": "director-1",
      "name": "Имя режиссёра",
      "enabled": true,
      "films": [
        {
          "id": "film-1",
          "title": "Название фильма",
          "original": "Original title",
          "year": 2001,
          "status": "pending"
        }
      ]
    }
  ]
}
```

`enabled` и `status` добавлены для редактора; исходные JSON-наборы без них импортируются.
Перед передачей игре служебные поля удаляются. Примеры: `examples/catalog.json`, `examples/films.csv`.
CSV-заголовки: `director_id;director_name;film_id;title;year;original;status`.
Первые пять обязательны; разделитель — запятая, точка с запятой или табуляция.
Поддерживаются BOM, CRLF, кавычки, двойные кавычки и переносы внутри экранированного поля.

CSV-экспорт защищает текст от выполнения формул в табличных редакторах. Это может добавлять
апостроф перед такими значениями. Для точного обмена используйте JSON: CSV не сохраняет
отключение режиссёра и метаданные версии, а импорт в любом случае возвращает фильмы на проверку.
Прямой импорт XLSX не реализован: сохраните таблицу как CSV UTF-8.

## Релизы: код + каталог

```text
Сборка игры v06 ──┐
                  ├── релиз classic-1 ── основная ссылка
Каталог №1 ───────┘

Та же v06 + другой опубликованный каталог → отдельный релиз classic-2
```

Сборка кода регистрируется разработчиком в `config/rr-game-builds.json` и сначала загружается
на сервер. Администратор нажимает «Обновить список сборок», после чего связывает её с каталогом.
Черновик релиза открывается только администраторам. «Опубликовать» разрешает запуск подписчикам,
но не меняет основную версию. «Сделать основным» переключает обычные новые запуски.

В комплекте по умолчанию создаются `classic-1` и каталог `original-201-v1` из настоящего
встроенного набора. Инициализация выполняется только при отсутствии состояния в БД;
повторный деплой не сбрасывает коллекции, историю или выбранный релиз.

### Ссылки и приоритет параметров

| Запуск | Поведение |
|---|---|
| `/` | Текущий основной релиз из БД |
| `/?release=classic-1` | Именно указанный релиз и его каталог |
| `/?game=v06` | Выбранный опубликованный релиз этой сборки |
| `/?game=v1` | То же через псевдоним исходной v06 |
| Telegram `startapp=release_classic-1` | Указанный релиз |
| Telegram `startapp=game_v06` | Выбранный релиз указанной сборки |
| Telegram `startapp=admin` | Экран управления; сам параметр не предоставляет права |
| `/admin.html` внутри Mini App | Проверка административного доступа и редактор |

Пример Telegram-ссылки: `https://t.me/BOT_USERNAME?startapp=release_classic-1`.
Замените `BOT_USERNAME` на username вашего бота. При доступности Bot API `getMe` админка
подставляет его автоматически при копировании ссылки.

Приоритет: явный `release` → явный `game` → проверенный `ctx.initData.start_param` → основной релиз.
Параметр `game` выбирает не «случайный последний» каталог, а отдельную настройку для этой сборки.
Кнопка «Сделать основным» меняет и общий default, и выбор для `game` этой версии;
«Выбрать для ?game» меняет только второй указатель.

Несуществующий, несовместимый или закрытый релиз даёт понятную ошибку, без молчаливого перехода
к другой игре. Параметры никогда не трактуются как файловый путь, внешний URL или Git-ветка.
Обычная браузерная вкладка без Telegram initData не авторизует пользователя.

### Старые игры и сохранения

Работающая партия не опрашивает default и не получает подменённый каталог. Загрузчик фиксирует
релиз в URL, версия каталога опубликованного релиза неизменяема. Новые сохранения разделены по
Telegram ID, коду, релизу, версии каталога и исходному fingerprint набора.
Оригинальное сохранение v06 копируется в новый namespace только для `classic-1`; старый ключ
не удаляется. Прогресс локальный, не синхронизируется между телефонами, может быть удалён очисткой
данных браузера. Старое сохранение не знало пользователя; на общем устройстве нельзя доказать,
кому оно принадлежало, поэтому перенос является удобством, а не защищённой миграцией аккаунта.

Для продолжения старой партии откройте её опубликованный релиз по ссылке. Обычный новый запуск
намеренно выбирает актуальный default, а не автоматически возобновляет другую версию.
«В архив» закрывает будущие запуски, в том числе продолжение после закрытия приложения.
Не архивируйте релиз, который ещё нужен игрокам: оставьте его опубликованным, при необходимости
в режиме «по ссылке». Уже открытая партия от архивирования сама не прерывается.

## Устройство проекта и сборка

| Путь | Назначение |
|---|---|
| `src/rr-legacy-v06.html` | Настоящий исходник игры; создаётся один раз из текущего `public/index.html` |
| `src/rr/` | Исходники загрузчика, админки, валидации, импорта, сервисных правил |
| `public/index.html` | После сборки — постоянный загрузчик релиза |
| `public/admin.html`, `public/rr/` | Клиентская админка; здесь никогда нет CLI token или allowlist |
| `public/games/<id>/<hash>/index.html` | Неизменяемые игровые сборки, сохраняемые в Git |
| `public/rr/runtime/`, `public/rr/frozen/` | Зафиксированные загрузчики и локальные script-зависимости игры |
| `config/rr-game-builds.json` | Разрешённые исходники кодовых версий |
| `config/rr-built-games.json` | Создаваемый сборкой реестр путей, SHA-256 и зависимостей; хранить в Git |
| `tgcloud/lib/rr/` | Авторизация, правила, SQLite, сгенерированный seed/реестр |
| `tgcloud/endpoints/rr*.js` | Административное API, запуск релиза, smoke endpoint |
| `scripts/rr-prepare.cjs` | Проверка/сборка, сохранение игры, добавление схемы; без сети и деплоя |
| `scripts/rr-check.cjs` | Локальные тесты и проверка целостности собранных файлов |
| `scripts/rr-deploy.cjs` | Только явная последовательность production-публикации |
| `scripts/rr-package.cjs` | Полный ZIP объединённого checkout после сборки; без локальных секретов |

Требуется Node.js 22. Обычная локальная сборка:

```bash
node scripts/rr-prepare.cjs
node scripts/rr-check.cjs
```

`rr-prepare` не очищает `public` и не удаляет старые сборки. Он сохраняет существующую схему,
добавляет экспорт новой таблицы, обновляет static-конфигурацию и переводит `npm run check` на
новые проверки. Прежняя команда сохраняется как `check:legacy`; её старые предположения о корневом
HTML требуют отдельной адаптации, она не является частью новой автоматической проверки.
Существующие зависимости `package.json` не заменяются; изменение scripts не требует пересчёта lockfile.

Сборщик проверяет ожидаемые места интеграции (`launchArchive`, `SAVE_KEY`, JSON-блок).
Если они изменились, он прекращает работу до изменения файлов. Не отключайте эти проверки.
Старые кодовые сборки не пересобираются новым runtime автоматически: исправление игровой сборки
должно получить новый ID, чтобы не менять уже опубликованный релиз.

Для ещё одной совместимой версии положите новый исходный HTML в `src/`, добавьте запись с новым ID
и `adapter: "v06"`, выполните сборку, проверки и деплой. Эта опция означает совместимость с контрактом
v06, а не универсальную поддержку любой механики. Для голосования/другой схемы нужен новый адаптер
и серверная проверка совместимости; текущая реализация остановится, а не попробует исполнить его вслепую.

## База и пределы MVP

Логические сущности: `game_versions`, `catalog_versions`, `game_releases`, `app_settings`, `audit`.
**Физически в этой версии это один документ в одной строке SQLite `rr_admin_state`.**
Это намеренное упрощение для двух администраторов: сохранение выполняется одним условным
`UPDATE ... WHERE revision = ... RETURNING`, поэтому переключение default, изменения и запись
истории не расходятся между несколькими незавершёнными запросами. При конфликте обновление не применяется.
Транзакционный API платформы не выдуман; foreign keys не используются.

Лимиты приложения, не квоты Telegram: до 30 версий каталога, 100 релизов, 4 МиБ всего состояния,
200 последних записей истории; в одном наборе до 12 режиссёров, 500 фильмов, 300 на режиссёра.
Название фильма/оригинальное — до 140 символов; название набора/версии — до 100; имя режиссёра — 64;
ID — 1–64 символа `[a-z0-9][a-z0-9_-]*`; год — целое 1800–2100.

Это не безлимитная CMS: перед исчерпанием пределов нужен перенос на построчную модель и отдельный
неограниченный журнал. Полные snapshot-экспорты сохраняйте вне приложения. Автоматическое восстановление
всего состояния из резервной копии пока не реализовано; отдельный каталог можно импортировать в новый черновик.
