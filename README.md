# Красная комната · RedRooms

**Киноигра в Telegram для канала «Витальное кино»: создавать тематические подборки, проводить конкурсы, проверять результаты и публиковать итоги можно из админки — без изменения кода.**

[Репозиторий](https://github.com/ladohinpy/redrooms) · [Открыть тестовую игру](https://t.me/vitalkino_stage_bot?startapp) · [Войти в админку](https://t.me/vitalkino_stage_bot?startapp=admin)

## Игра

Игрок перемещается по 3D-комнате и раскладывает кассеты по столам. Подписи столов могут обозначать режиссёров, годы, номинации и любые другие категории. У каждой кассеты один правильный стол.

На компьютере используются клавиатура и мышь, на телефоне — джойстик, свайпы и кнопки. Есть пауза, выбор стороны управления и локальное сохранение прогресса. При ошибочном размещении появляется нейтральное сообщение: **«Неправильно. Точность снижена.»**

Вход в игру разрешён подписчикам настроенного канала. Запускать личный диалог с ботом для игры необязательно. На первом экране — название игры, явно заданное авторское вступление, количество кассет, управление и кнопка входа. Пустые авторские поля не создают заглушек.

После прохождения доступны очки, точность, результаты попыток, рейтинг, авторский финал и, когда разрешено, статья. Здесь же можно поделиться текстом со ссылкой **на конкретный набор** или скопировать ссылку; на стартовом экране этих кнопок нет.

## Вход в управление

Админка доступна **только двум Telegram ID**, заданным при публикации в `RR_ADMIN_IDS`. Проверка прав выполняется на сервере для чтения и изменения данных, статистики, предпросмотров и бэкапов.

Для подтверждённых администраторов кнопка **«Админка»** появляется на первом экране игры. Прямая ссылка выше открывает тот же редактор внутри Mini App. Обычный пользователь не получает доступ по этой ссылке и не видит административных кнопок. Редактор адаптирован для компьютера и телефона.

## Возможности админки

### Наборы и публикация

**«+ Новый набор»** создаёт форму с названием, кодом ссылки и четырьмя столами. Для каждого стола задаются подпись и список кассет. Названия вводятся по одному на строке или через точку с запятой; разделение запятыми включается отдельно. Годы и JSON для обычной работы не нужны.

| Действие | Результат |
|---|---|
| **Сохранить черновик** | Записать работу, не открывая её игрокам. Автосохранения нет. |
| **Опубликовать по ссылке** | Выпустить отдельный набор, не меняя основную игру. |
| **Опубликовать и сделать основным** | Выпустить набор и выбрать его для новых обычных запусков. |
| **Сделать основным** | Переключить основной набор на уже опубликованный; повторный деплой не нужен. |
| **Создать копию** | Скопировать кассеты, правильные ответы и авторские материалы в новый черновик без результатов и статистики исходного выпуска. |
| **Копировать / открыть / отправить ссылку в бота** | Получить отдельную ссылку на набор; отправка — только самому администратору. |

Перед публикацией проверяются заполненность, дубли и ограничения набора. Опубликованные кассеты и правильные ответы фиксируются: для изменения состава создаётся копия. Старые ссылки продолжают вести к прежним наборам. Несохранённые изменения отмечаются, а конфликт одновременного редактирования не позволяет молча затереть чужую работу.

### Материалы

Для каждого набора редактируются **внутреннее описание**, вступление под заголовком «Красная комната», два финала — успешный и ниже порога — и отдельная авторская статья. У материала есть заголовок, текст, необязательная ссылка и её подпись. Поддерживаются абзацы, жирный, курсив и текстовые ссылки; есть предпросмотры материалов и набора.

Порог успешного финала настраивается по точности, по умолчанию — **80%**. Статью можно скрыть, открыть после окончания конкурсного окна либо после двух израсходованных и закрытых попыток. Внутреннее описание и ещё закрытая статья игроку не передаются. Тексты сохраняются отдельно: исправление статьи не меняет правильные ответы и не требует новой публикации кода.

### Конкурс

Можно вручную начать конкурс, указать окончание, продлить его до фиксации итогов, завершить конкурсное окно и **опубликовать окончательные итоги**. Планируемая дата начала служит для списка выпусков, а не запускает конкурс автоматически.

**Публикация набора, выбор основной игры и начало конкурса — три разных действия.** Без активного конкурса набор доступен для свободного прохождения. После закрытия окна идёт проверка результатов; после публикации итогов набор остаётся доступным вне зачёта. Проверки администратора не участвуют в конкурсном рейтинге.

### Статистика

По выбранному выпуску показываются начавшие и завершившие игроки, число попыток и вторых попыток, средний лучший балл, максимум, доля завершения, попытки для проверки, архивные прохождения и поздние результаты. Отдельно видно, на каких кассетах чаще ошибались.

В таблице участников — первая и вторая попытки, лучший балл, место, дата финиша и статус. Фильтры: все, лидеры, использовавшие второй шанс, требующие проверки, исключённые и незавершённые. Из таблицы открывается история игрока. Предварительный рейтинг отличается от зафиксированных официальных итогов.

### Игроки и модерация

Поиск работает по Telegram ID, username и имени. Карточка показывает первое появление, последнюю активность, наборы, попытки, исходные ответы, действия и серверный расчёт. **«Всего попыток»** включает зарегистрированные начала, незавершённые игры и административные проверки; **«Проверки»** вынесены в отдельный счётчик. Простое открытие приложения попыткой не считается.

Администратор может подтвердить результат, пометить его для проверки, скорректировать зачётный балл, технически аннулировать попытку с возвратом слота, исключить игрока из текущих и будущих рейтингов или восстановить его. Решения требуют объяснения и сохраняют автора, время и изменения. Первоначальные ответы и расчёт не переписываются; исключение из рейтинга не запрещает играть.

**Опубликованные итоги неизменяемы.** Позднее исключение игрока не меняет старые места, баллы и имена — добавляется административная пометка. Новый конкурс проводится на копии набора. Автоматических банов нет.

### Публикации и выпуски

Раздел **«Публикации»** готовит анонс, напоминание, итоги или пост об архивном выпуске. Подставляются данные набора, ссылка, сроки, участники и результаты; можно выбрать число мест в топе, отредактировать текст, сохранить черновик, посмотреть предпросмотр и скопировать пост или ссылку. Отправка в канал остаётся ручной.

Раздел **«Выпуски»** показывает конкурсы, их состояние, планируемое начало, фактическое начало и окончание. Автозапуска и автоматического переключения основного набора нет.

### Резервные копии

Можно скачать свежий полный **JSON** с сервера, отправить его обоим администраторам в личные чаты с ботом, загрузить копию, проверить её состав и подтвердить восстановление. В копию входят наборы, материалы, конкурсы, игроки, попытки, действия, модерация и официальные итоги; секретов в ней нет.

Перед восстановлением обоим администраторам отправляется страховочная копия текущих данных. Применение выполняется после проверки и отменяется при конфликте с новыми записями. Старый файл не может незаметно стереть или заменить опубликованные итоги.

Предусмотрены бэкап перед обновлением и ежедневный GitHub Action **`Red Room — Private JSON Backups`** в **03:17 UTC**. Автоматические копии требуют настроенных переменных и работающего workflow; бэкапы боевой среды включаются отдельно. Администраторы должны разрешить боту личные сообщения. JSON содержит пользовательские данные: храните его приватно, не в публичном репозитории. Код игры сохраняется отдельно.

### Дополнительные инструменты

**«Подробный редактор»** работает с той же базой: отдельные карточки фильмов, годы и оригинальные названия, перенос между столами, включение категорий, модерация «На проверке / Одобрен / Исключён», массовые действия и поиск. Доступны импорт JSON/CSV/TSV, экспорт JSON/CSV, управление связками каталога и сборки игры, предпросмотр релизов и журнал изменений.

Действие **«В архив» в подробном редакторе релизов закрывает новые запуски ссылки**. Это не конкурсный архив: завершённый конкурс остаётся играбельным. Не используйте снятие релиза с публикации вместо завершения конкурса.

## Правила попыток и результатов

| Правило | Как работает |
|---|---|
| Очки | **+100** за правильное размещение, **−75** за ошибку. |
| Точность | Доля верных размещений среди всех попыток размещения, в процентах. |
| Конкурс | Две зачётные попытки на набор; в рейтинг идёт лучшая. При равных баллах место общее. |
| Учёт | Начало регистрирует сервер. Повтор запроса не создаёт новую попытку, очистка localStorage не снимает лимит. |
| Возобновление | Сохранившийся локальный прогресс продолжает ту же попытку. Потеря прогресса не возвращает слот автоматически. |
| Финиш | Сервер проверяет ответы и пересчитывает результат; неподтверждённый финиш остаётся на устройстве для повторной отправки. |
| Сроки | Зачёт определяет время получения сервером. Поздний результат сохраняется вне зачёта. |
| Архив и проверки | Свободные прохождения и проверки администратора не меняют конкурсные итоги. |

Состояние попытки сверяется с сервером; потерянное подтверждение сохранённого результата можно восстановить без дубля. Подозрительные расхождения сохраняются для ручной проверки. Это контроль аномалий, а не гарантированный античит: данные действий на клиенте могут быть подделаны.

## Как выпустить новую игру

**Создать или скопировать набор → заполнить четыре стола → сохранить → добавить материалы → опубликовать по ссылке → проверить → при необходимости сделать основным и начать конкурс → проверить результаты → закрыть окно → опубликовать итоги и скопировать пост.**

Для повседневного изменения наборов, текстов, сроков и основного выпуска GitHub не нужен. Администратор проверяет игру вне зачёта; конкурсные ограничения проверяются обычным подписанным аккаунтом.

## Данные, обновления и ограничения

Приложение использует Telegram Mini Apps, Telegram Serverless и SQLite. Наборы и история хранятся на сервере; незавершённая раскладка — локально на устройстве, без полной синхронизации между телефонами. Реализованы отдельные сценарии публикации на тест и бой с разными ключами, проверкой назначения и бэкапом перед изменениями.

Наблюдаемая аналитика учитывает открытия Mini App, запуски с параметром набора и увиденные приложением переходы «не подписан → подписан». Она **не измеряет** число репостов, запусков чата бота или приглашений конкретных друзей.

Текущие пределы: до **500 кассет** в наборе, до **300 на стол**; простой редактор — четыре стола, подробный — до 12 категорий; импорт — до **1 МиБ**, полный бэкап — до **40 МиБ**. Редакторская база ограничена 30 версиями каталога и 100 релизами. Это версия для небольшого сообщества; автоматического разбиения бэкапов и очистки служебной истории нет.

Пока не реализованы картинки результатов, сторис, нативный медиа-шаринг, QR-коды, персональные реферальные ссылки и автопостинг в канал.

### Для обновления кода

```sh
node scripts/rr-prepare.cjs
node scripts/rr-check.cjs
```

После проверок используется ручной GitHub Action публикации для нужной среды. Не удаляйте базу и старые игровые сборки. После миграции на `rr_records` нельзя возвращать backend, работающий только со старой `rr_admin_state`. Локальные тесты не заменяют проверку входа, прохождения и доставки бэкапов в настоящем Telegram.
