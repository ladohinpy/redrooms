# Красная комната — наборы кассет и четыре стола

Админка: TABLES ADMIN 2. Исправление публичного интерфейса: **PLAYER UI 1**, совместимая сборка `v08-player-ui`.
Служебные версии не показываются игрокам. [Установить исправление](docs/HOTFIX-PLAYER-UI.md).
Проект: `ladohinpy/redrooms`. Патч накладывается на актуальный `main` с уже применёнными исправлениями CLI, схемы и static headers.

## Что видит редактор

Админка — **отдельная страница «Наборы кассет»**, а не меню JSON внутри 3D-игры.
В верхней части явно показано, какой набор запускается по умолчанию. Слева — сохранённые наборы.
В редакторе — название набора, его код для ссылки и четыре строки:

| Надпись на столе | Кассеты, подходящие к этому столу |
|---|---|
| Любая категория, режиссёр или год премии | Названия по одному на строке |
| Вторая категория | Список названий |
| Третья категория | Список названий |
| Четвёртая категория | Список названий |

Годы, оригинальные названия, JSON и технические ID отдельных кассет вводить не надо.
У нового фильма без года в данных хранится `null`, не вымышленный год. Старые корректные годы сохранены.
Названия столов могут быть произвольными: «Оскар 2027», «Лучшая музыка», «Куросава» и т. п.
Надписи — редакционный контент; приложение не проверяет факты о премиях и фильмах.

## Как войти

1. В BotFather у нужного бота проверьте URL **Main Mini App**. Для текущего приложения он должен быть:
   `https://app8804859840.tgcloud.ai/`
2. Если есть отдельная кнопка меню/кнопка со старой ссылкой, проверьте и её. Настройка старой кнопки не меняется от деплоя.
3. Откройте внутри Telegram `https://t.me/BOT_USERNAME?startapp=admin`, заменив имя на username **бота**, не канала.
4. Только после подтверждения административных прав появляются «Наборы кассет» и ваш ID. До этого экран нейтрален.

В игре кнопка «Управление наборами» появляется только после `isAdmin === true` в серверном ответе. В публичном загрузчике ссылки управления нет. Администраторы могут входить напрямую через `startapp=admin`, не ожидая 3D-сцены.

Обычный пользователь при прямом переходе на `/admin.html`, `/admin-advanced.html` или `startapp=admin` направляется в обычную игру. Подписка по-прежнему проверяется. До проверки прав и при отказе не показываются редактор, ID аккаунта и сообщения о двух администраторах. Публичные ошибки не выводят сырые серверные сообщения, коды, этапы или диагностику.

**Если видите «Набор фильмов и освещение», «Загрузить JSON» поверх комнаты — это старый локальный экран игры, не эта админка.**
Скриншот такого экрана сам по себе не доказывает, какой URL открыл Telegram. Проверьте адрес, который указан в BotFather, не отправляя никому `tgWebAppData`.

Для полноценной работы используйте Telegram Desktop или Telegram Web с запуском Mini App через бота.
Новая админка — обычная прокручиваемая страница, не большое фиксированное окно поверх сцены. Поля списков можно растягивать по высоте.
Само системное окно Telegram сайт перемещать не может. Открытие голого URL в обычной вкладке без Telegram initData прав не предоставляет;
отдельный логин через Telegram Login Widget/OIDC в этом патче не добавлен.

## Создание и публикация

- **«+ Новый набор»** — четыре пустых стола, код генерируется автоматически; можно заменить его, например на `oscar-2027`.
- **«Сохранить черновик»** — записывает работу в базу, ничего не меняя для игроков. Автосохранения нет.
- **«Опубликовать по ссылке»** — публикует набор отдельно, не переключая основную игру.
- **«Опубликовать и сделать основным»** — публикует и выбирает набор для всех новых обычных запусков.
- **«Сделать основным»** у опубликованного набора — переключает основной набор, без новой загрузки кода и без нового ключа.
- **«Создать копию»** — начало редактирования опубликованного набора. Старый набор и его ссылка сохраняются.

Публикация создаёт опубликованный каталог и релиз **одной атомарной записью**. Дополнительное ручное создание связки «код + каталог» для этого сценария не требуется.
По-прежнему есть серверная проверка двух ID и контроль ревизии. Если другой администратор успел сохранить правки,
устаревшая запись отклоняется, текст остаётся на экране: сначала скачайте черновик, затем обновите данные.
После сетевого таймаута не повторяйте публикацию вслепую — запрос мог успеть сохраниться.

Опубликованная версия неизменяема. Уже запущенная игра не подменяет свой набор при изменении основного релиза.
Для возврата выберите прежний опубликованный набор и нажмите «Сделать основным».

## Форматы ввода и ограничения

Рекомендуется одна кассета на строке. В режиме «Авто» переносы строк имеют приоритет; если переносов нет, распознаётся `;`.
Для списков со смешанными переносами и `;` выберите «Точка с запятой». Разделитель-запятая выбирается **явно** — иначе
«Однажды, в Голливуде» был бы ошибочно разбит на две кассеты. При наличии запятой внутри названия используйте строки.

Ровно четыре стола; для публикации каждому нужны уникальная надпись и хотя бы одна кассета.
Надпись стола — до 64 символов, название кассеты — до 140. Суммарно до 500 кассет, до 300 у одного стола.
У одной кассеты один правильный стол. Одинаковые названия в нескольких категориях запрещены: удалите дубль или уточните название.
Механика нескольких правильных столов не добавлена.

Импорт JSON и экспорт черновика остаются дополнительными инструментами, а не обязательным способом работы.
Формат `red-room-tables` приведён в `examples/four-tables.json`; импорт старого JSON-каталога до четырёх столов тоже поддерживается.
Импорт изменяет только текущую форму до явного сохранения/публикации. Прямой импорт XLSX не добавлен.
Старый подробный редактор (CSV/JSON, модерация, версии кода, архивирование) сохранён по кнопке «Подробный редактор».
Он работает с той же базой; это не независимое хранилище. Каталоги больше четырёх столов редактируйте там.

## Ссылки на наборы и получение через бота

После публикации готовая ссылка показана прямо в панели:

```text
https://t.me/BOT_USERNAME?startapp=set_oscar-2027
```

Параметр называется **`startapp`**, не `startup`. Код набора — 1–56 символов: латинские строчные буквы, цифры, `_`, `-`.
Имя бота определяется сервером через `getMe`. Если это не удалось, панель позволяет ввести username для формирования ссылки — это не влияет на права.

Кнопки: **«Копировать ссылку»**, **«Открыть набор»**, **«Отправить ссылку мне в бота»**.
Последняя вызывает `rrSendSetLink` и отправляет сообщение только проверенному администратору, вызвавшему запрос.
Произвольный получатель из браузера не принимается. Для получения сообщения может понадобиться сначала открыть личный чат с ботом и нажать «Начать».
Рассылка подписчикам, новая команда `/start`, изменение webhook и доступ к чужим чатам не добавляются.

Поддерживаются прежние `startapp=release_classic-1`, `startapp=game_v06` и веб-параметры `release`, `game`.
Обычный запуск выбирает основной набор, явная ссылка — конкретный опубликованный релиз. Неверный ID даёт ошибку, не случайный другой набор.
Режим «по ссылке» не является секретным/приватным: ссылку можно переслать, доступ требует обычной подписки.

## Что исправлено в загрузке и интерфейсе

**Воспроизведённый дефект старого загрузчика:** сравнение `location.pathname` с `/.../index.html` буквально.
Если хост отдаёт тот же файл по `/.../`, старый код снова вызывает навигацию и ожидает бесконечно.
Тест воспроизводит это с настоящим старым `engine-boot`; новый код принимает эквивалентные пути, ограничивает переходы,
останавливает заблокированную навигацию вместо бесконечного ожидания. Игрок видит обычное сообщение с повторной попыткой, без служебных этапов.

Это доказанный дефект кода и подходящий сценарий зависания, но фактический редирект в пользовательской Telegram-сессии
не был снят сетевым трассированием. Старый URL бота, кэш или проблема SDK могут иметь другой источник: теперь есть диагностика.

SDK имеет ограничение ожидания 12 секунд, вызов сервера — 15, переход — 5. Начальные HTML-страницы имеют watchdog отсутствующего модуля.
Внутренняя диагностика содержит этап, pathname и версию, **без initData, токенов и query/hash авторизации**. Она не выводится на экран игрока. Публичной кнопки копирования диагностики больше нет.

Десктоп: отдельная страница редактора и центрированная прокручиваемая стартовая карточка игры.
Телефон: учитываются `safeAreaInset`, `contentSafeAreaInset` и события изменения области, выход из fullscreen в админке.
Кнопки игры и статистика расположены ниже верхней панели; уведомления закрываются вручную, успешные также исчезают автоматически.

## Версии, сохранения и обратная совместимость

Оригинальный `src/rr-legacy-v06.html`, опубликованный HTML v06 и его frozen/runtime-файлы оставлены побайтно неизменными.
Новый исходник `src/rr-game-v07.html` компилируется в отдельную неизменяемую сборку `v07-tables` с собственным хешем.
**Не редактируйте опубликованный v07 под тем же ID после этого выпуска** — следующий выпуск кода должен получить новый ID.

В `rrGetLaunch` есть явное совместимое отображение только для известной v06 с хешем
`05ac2cca6a93c5b2701898f807c2c2d3e4a840216aec975e28d003ff09427749`:
её сохранённые release/catalog/game идентификаторы остаются прежними, но дополнительное поле `runtime` выбирает исправленную v07.
Таким образом обычная ссылка `classic-1` получает исправленный загрузчик и интерфейс без переписывания каталога/основного указателя.
Неизвестные сборки автоматически не подменяются. Это совместимый renderer-переход, **не миграция пользовательской базы**.
Старые прямые URL frozen `/games/v06/...` сохранены как артефакты; для запуска используйте корень Mini App и `startapp`, а не эти файлы.

Старый namespace прогресса для classic-1 сохраняется. Новый набор имеет собственный namespace, прогресс не синхронизируется между устройствами.
Старый полный редактор сохраняет свои механизмы каталога/релизов. Новые каталоги с отсутствующими годами нельзя связать со старым кодом,
который требует число: сервер отклонит это и предложит v07.

Схема SQLite `rr_admin_state` **не меняется**, команды удаления/сброса БД не добавлены.

## Установка, публикация, проверки

Начните с [START-HERE.md](START-HERE.md) и [FIX-TABLES-ADMIN-V2](docs/FIX-TABLES-ADMIN-V2.md).
Node.js 22, прежний CLI 0.2.0 с ранее добавленным локальным guard. Ключ и два ID хранятся как раньше, не в ZIP.

```bash
node scripts/rr-prepare.cjs
node scripts/rr-check.cjs
```

Проверки включают синтаксис каждого JS-модуля (а не только unit-тесты), 238 unit/integration-тестов и хеши всех frozen-файлов.
Браузерный офлайн-тест запускается отдельно, не в production workflow:

```bash
# После установки Python Playwright и Chromium. На Linux без дисплея можно использовать Xvfb.
DISPLAY=:99 python tests/rr/browser-tables-offline.py

# Отдельные проверки публичного интерфейса, с локальным сервисом на порту 4198:
RR_TEST_PORT=4198 node tests/rr/runtime-browser-server.mjs
# В другом терминале:
DISPLAY=:99 RR_TEST_PORT=4198 python tests/rr/browser-player-ui.py
```

Он использует настоящие HTML/JS/WebGL, но тестовые SDK/ID и in-memory backend. 39 проверок проходят на desktop и узком viewport.
Дополнительно 30 браузерных проверок проверяют отсутствие административных элементов у постороннего пользователя, нейтральный экран до авторизации, сохранение работы обоих администраторов и запуск 201 кассеты.
Это не нативный iPhone/Android и не проверка Telegram-подписи в живом аккаунте. Действующий сервер при подготовке патча не менялся.

После публикации можно отдельно проверить доступные публичные файлы и их хеши (только GET, без токена):

```bash
node scripts/rr-verify-static.cjs https://app8804859840.tgcloud.ai/
```

Этот скрипт не заменяет вход в Telegram, но обнаруживает другую/устаревшую статику и неправильный MIME-type модулей.
Не включён автоматически в деплой, чтобы временный CDN-сбой после успешной загрузки не выглядел как отказ всей публикации.

## Основные пути

- `src/rr/admin.{html,css,mjs}` — простая отдельная админка.
- `src/rr/simple.mjs` — четыре стола, строки, ссылки; `domain.mjs` — правила и атомарные команды.
- `src/rr/routes.mjs`, `client.mjs`, `launcher.mjs`, `engine-boot.mjs` — запуск и диагностика.
- `src/rr-game-v07.html` — новый игровой исходник с необязательными годами.
- `tgcloud/endpoints/rrSendSetLink.js` — отправка ссылки только вызывающему администратору.
- `scripts/rr-prepare.cjs` — сборка; `rr-check.cjs` / `rr-syntax.cjs` — проверки.
- `scripts/rr-deploy.cjs` — прежняя последовательность с новым endpoint; запуск только с `--confirm`.
- `config/rr-built-games.json`, `public/games`, `public/rr/runtime`, `public/rr/frozen` — сохранять в Git, не чистить при деплое.

## Исправление PLAYER UI 1

Публичный экран: «Красная комната», «Игра канала „Витальное кино“», просьба подписаться и ровно две кнопки: открыть канал и проверить снова. При других ошибках — нейтральное сообщение и повторная попытка.
Адрес проверяемого канала не изменён: он по-прежнему приходит из действующей серверной конфигурации (`@redrooms_stage` в исходном проекте). Новое название — подпись интерфейса, не автоматическая замена канала.

Клиентское скрытие не заменяет серверную авторизацию. `rrAdminRead`, `rrAdminCommand` и отправка ссылки продолжают проверять права на сервере. Ни URL, ни `isAdmin` из пользовательского запроса не дают прав.

Существующие файлы v06/v07 не переписаны. `rrGetLaunch` выбирает совместимый v08-рендерер для двух известных хешей v06/v07, сохраняя логическую версию игры, ID релиза и ключи сохранения. Сам `defaultReleaseId` не меняется, база не мигрируется. Исторические прямые адреса неизменяемых HTML-файлов сохраняются; для актуального интерфейса запускайте приложение через корень/бота, а не старую закладку `/games/v06/...`.
