# Медиа: результаты проверки, реализация отложена

Проверены официальные страницы Telegram 27.10.2026:
- https://core.telegram.org/bots/serverless
- https://core.telegram.org/bots/webapps#initializing-mini-apps
- https://core.telegram.org/bots/api#senddocument

## Base64
Внутри самой HTML-страницы можно показывать изображение через data:image/...;base64
или canvas/blob URL. Это способ доставки браузеру, а не публичный HTTPS-адрес.
Telegram Mini Apps shareToStory требует HTTPS media_url; data:/blob: не выполняют
этот контракт. Base64 не решает размещение картинки для native stories.
Встроенные изображения/логотипы можно добавить позже, но не помещать их в каждую
попытку и бэкап: base64 увеличивает объём исходных байтов примерно на треть.

## Что позволяет текущий сервер
Telegram Serverless SDK документирует InputFile из байтов и отправку документа/фото
через Bot API. Значит, JSON-бэкап действительно можно отправлять напрямую, без
собственного файлового сервера. Внешний HTTP upload через sdk/fetch тоже предусмотрен.

Статические картинки можно положить в public/ и публиковать вместе с кодом по HTTPS.
Но в проверенной документации нет готового API изменяемого публичного object storage
для произвольных персональных картинок прямо из пользовательского endpoint.
Загрузка файла в чат бота не делает его безопасной публичной ссылкой для сторис.
Нельзя публиковать Bot API file URL, содержащий токен бота, или давать клиенту CLI key.

Для следующего пакета нужен отдельно проверенный путь: статические шаблоны плюс
генерация/временное хранилище, либо поддерживаемый Telegram способ подготовленного
медиа-сообщения. ShareMessage требует savePreparedInlineMessage; это не обычная
текстовая ссылка. HTTPS-картинки, Premium-сценарии story links и реальная доставка
на iOS/Android остаются на отдельный этап.

В текущем пакете: обычный Telegram-шаринг текстом и URL конкретного набора, без
картинки, native shareMessage, stories и персональных реферальных меток.
