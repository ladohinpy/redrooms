# RedRooms — исправление доступа и входа в комнату

Основа: присланный `redrooms-main (3).zip`, коммит `c137dae253cc7b69ee6fc3971c5445d054d88f27`.
Патч не создаёт новую админку: сохраняет действующий редактор, оформление и расположение функций.
Новая игровая сборка — `v11-access-entry`. Старые опубликованные игровые файлы не изменяются.

## Установка

1. Создайте от актуального `main` ветку `fix/admin-entry-access`.
2. Распакуйте ZIP и перенесите его содержимое в корень репозитория с сохранением папок.
   Замените совпадающие файлы, остальные оставьте. Не кладите ZIP как один файл в GitHub.
3. Объедините проверенный PR с `main`. Запустите новый `Run workflow`:
   **Publish Red Room — Admin & Releases → main → PUBLISH**.
4. Используйте существующие `TGCLOUD_TOKEN`, `RR_ADMIN_IDS` и `RR_STAGE_BOT_USERNAME`.
   В `RR_ADMIN_IDS` должны оставаться ровно два ваших разных положительных числовых ID.
   Патч не содержит реальных ID и не меняет их. Не заменяйте список тестовыми числами.
5. После успешной публикации полностью закройте прежнее окно Mini App и откройте бота заново.
   У Павла и Виталия на первом экране игры должна появиться кнопка **«Админка»**.
   Она открывает существующее управление в том же WebView, а не внешний браузер/новое окно.

Схема базы, попытки, результаты, архивы итогов и резервные копии этим патчем не изменяются.
Не очищайте localStorage/базу, не применяйте `--force`. Штатный бэкап перед публикацией сохраняется.
Старые прямые адреса frozen `/games/v10-clean-start/...` не переписываются: используйте обычный
запуск Mini App (корневой адрес), чтобы сервер выбрал исправленный renderer.

## Доступ

- Сервер проверяет только `ctx.initData.user.id`, заверенный платформой, против ровно двух ID.
- Username, ID из тела запроса, `startapp=admin`, localStorage и отображение HTML прав не дают.
- Чтение редактора, изменения, статистика, предпросмотр, отправка ссылок, бэкапы и восстановление
  требуют прав на сервере. Входная проверка выполняется до инициализации хранилища.
- Редактор скрыт до свежей проверки роли И успешного защищённого чтения с тем же ID.
- При отказе открытый интерфейс очищается. Возврат страницы из BFCache требует новой проверки.
- Непрошедший проверку пользователь возвращается к обычному запуску с действующей проверкой подписки.
- HTML/JS приложения публичны как статические файлы; это не доступ к данным и операциям.

Прямая ссылка остаётся прежней: `https://t.me/vitalkino_stage_bot?startapp=admin`.
Она не предоставляет права постороннему аккаунту. Новая обязательная регистрация не добавлена.

## Подтверждённые исправления

1. В CLEAN START админская кнопка была оставлена только в меню паузы. Теперь она есть и на первом
   экране, но только после серверного подтверждения роли. Перед переходом роль перепроверяется.
2. Ошибка регистрации попытки показывалась через игровой toast внутри ещё скрытого HUD.
   Теперь короткое безопасное сообщение видно рядом с кнопкой входа. Пока запрос идёт, показан
   статус и заблокирован параллельный повтор. Ошибка не считается успешным началом игры.
3. Повтор после потерянного подтверждения использует тот же requestId, не расходует новую попытку.
4. Мобильная сетка редактора ограничена шириной WebView: одна колонка, перенос длинных строк,
   прокручиваемые таблицы, ограниченная ширина диалогов. Исходная цветовая схема сохранена.

## Что ещё не подтверждено на живом сервере

Точная причина серверного отказа запуска в пользовательской сессии неизвестна: серверный ответ
не был приложен, а подписанные сессии Павла/Виталия/игрока недоступны в среде разработки.
Исходный архив уже содержал проверки административных ID; факт выдачи сервером полномочий
постороннему аккаунту по одному скриншоту не установлен. Патч усиливает реальную проверку,
не заменяет её скрытием кнопок, но не выдаётся за аудит опубликованной живой конфигурации.

Локально запуск реальной сцены проверен для обоих администраторов и обычного подписчика.
Если Telegram продолжит отклонять начало попытки, патч покажет сообщение вместо молчания.
Не следует выдавать такую диагностику за доказательство исправления ещё неизвестной облачной причины.

## Приёмка после публикации

- Ваши два аккаунта: «Админка» видна ДО запуска комнаты; переход остаётся внутри той же Mini App.
- Обычный аккаунт: кнопки нет, прямой admin-вход не показывает редактор/ID и возвращает к игре.
- На телефоне: никакой горизонтальной полосы прокрутки всего редактора, поля помещаются в экран.
- Все три аккаунта: нажать «Войти в архив». При успехе стартовая карточка исчезает.
  При отказе сообщение видно под ней; сырой SQL, токены, Telegram ID и технические детали не выводятся.
- При ошибке не повторять Publish вслепую и не очищать данные; достаточно текста видимого сообщения.

## Проверки

- 354 автоматические проверки пройдены (321 прежняя и 33 новых).
- 32 целевые браузерные проверки пройдены: две роли, прямой отказ, отзыв роли, размеры 360/390/1280,
  обычный и административный запуск настоящей WebGL-сцены, потерянное подтверждение и повтор.
- Использованы реальные модули UI/игры/сервиса и локальная SQLite, но тестовые Telegram ID,
  транспорт и перехват навигации. Это НЕ нативный Telegram и НЕ запуск в облаке с вашим ключом.
- Полный прежний браузерный прогон не завершился в этой среде (недоступный программный WebGL-контекст
  после ряда сцен); успешными заявлены только 32 целевые проверки. Он не подменён фиктивным успехом.
- Подписка и правила очков не переписаны. Замороженные v06–v10 и старые runtime/frozen побайтно сохранены.

Ни код, ни миграции, ни изменения данных из среды подготовки на ваш сервер не отправлялись.
