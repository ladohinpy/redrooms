# Исправление публикации интерфейса: X-Content-Type-Options

Дата: 21 октября 2026. Основа: присланный main + предыдущий патч CLI snapshot.

## Что подтвердил новый журнал

В журнале «Вставленный текст(1).txt»:

- Прошли 151 локальный тест.
- `tgcloud fetch` получил 15 модулей, серверная revision 3.
- Публикация серверных модулей: `No changes to deploy`.
- `migrate --dry-run` показал создание `rr_admin_state`.
- `migrate --safe` успешно применил одно изменение: таблица создана.
- `tgcloud run endpoints/rrHealth` ответил:
  `{ok:true,revision:1,defaultReleaseId:'classic-1',catalogs:1,games:1}`.
- Ошибка появилась только при `tgcloud push public/`, на `Preparing static version`:
  `Header can not be set: X-Content-Type-Options (field: headers, rule: 0)`.

`revision:1` в ответе rrHealth — версия данных приложения, а revision 3 у fetch —
ревизия опубликованных модулей. Это разные счётчики; само различие не означает конфликт.

Успешный CLI run — контрольный запуск кода с CLI-контекстом в облаке и доступом к БД,
а не полная проверка всех опубликованных endpoint из Mini App.
В этом запуске серверный push не менял модули, поэтому журнал не доказывает,
что предыдущий адаптер обработки false был задействован для нового изменяющего push.

## Причина

Сборщик `scripts/rr-prepare.cjs` формировал правило для всех статических файлов:

```json
{
  "path": "/*",
  "set": {
    "Cache-Control": "no-store",
    "X-Content-Type-Options": "nosniff",
    "Referrer-Policy": "no-referrer"
  }
}
```

Сервер Telegram отказал в пользовательской установке `X-Content-Type-Options`.
Это подтверждённое ограничение для данного запроса; из лога нельзя заключить,
что Telegram сам выставляет этот заголовок или каков его полный список запретов.

Изменение только сгенерированного tgcloud.jsonc неустойчиво: перед каждым релизом
prepare снова формировал старое правило. Исправлен именно источник генерации.

## Что делает патч

1. Убирает `X-Content-Type-Options` из генерируемого общего правила.
2. Убирает его из приложенного tgcloud.jsonc. Остаются `Cache-Control: no-store`
   и `Referrer-Policy: no-referrer`.
3. Добавляет локальную проверку известного несовместимого имени, включая другое
   написание регистра и попытку указать null. Это не полная копия серверной проверки.
4. Проверяет сохранившиеся правила для отдельных путей до записи файлов сборки.
   Если в них есть запрещённое имя, сборка останавливается, не удаляя настройки молча.
5. `rr-check.cjs` проверяет реальную конфигурацию перед тестами. В текущем deploy
   эта проверка выполняется до первого облачного вызова.
6. Добавляет 15 регрессионных тестов. Остальные 151 тест сохранены.

Существующее поведение сборщика для общего правила `/*` сохранено: это управляемое
правило, которое пересоздаётся при подготовке; частные правила сохраняются.
Патч не меняет базу, административные права, проверку подписки, игровой код,
каталог, старые игровые сборки, CLI-адаптер, ключ или workflow публикации.

## Применение через GitHub

1. Создайте от текущего main ветку `fix/static-headers`.
2. Распакуйте ZIP и перенесите его содержимое в корень репозитория, сохранив пути.
   Например, `scripts/rr-prepare.cjs` должен заменить файл в папке scripts,
   а не появиться в корне. Сам ZIP загружать как исходник не нужно.
3. Проверьте список изменений, сохраните commit, объедините PR с main.
4. Запустите НОВЫЙ Run workflow: `Publish Red Room — Admin & Releases`, main,
   подтверждение PUBLISH. Используйте прежние TGCLOUD_TOKEN и RR_ADMIN_IDS.

Этот пакет предполагает, что предыдущий CLI snapshot fix уже установлен,
как показывает строка `CLI 0.2.0 response guard ready` в последнем журнале.
Он не заменяет весь проект и не отменяет предыдущие исправления.

Если после присланного main вы самостоятельно меняли tgcloud.jsonc, не стирайте
свои настройки целиком: обновите скрипты и тесты, затем выполните prepare,
проверьте diff конфигурации. Игровые исходники и настройки доступа не трогайте.

## Проверки перед публикацией

В рабочей копии:

```bash
node scripts/rr-prepare.cjs
node scripts/rr-check.cjs
```

Без RR_ADMIN_IDS локальная подготовка создаёт закрытый список администраторов
без записей; это НЕ production-публикация. Штатный Action перед публикацией
повторно выполняет `--production` с двумя ID из уже существующих настроек.

Новый маркер проверки:

```text
STATIC HEADER PREFLIGHT OK (known X-Content-Type-Options restriction).
```

После уже успешной миграции ожидается отсутствие изменений схемы, если никто
не менял её отдельно. Это не повод удалять или заново создавать таблицу.
Не выполняйте сброс БД, не отключайте проверки и не используйте --force.
Ручное подтверждение в BotFather для устранения этой ошибки не требуется.

После завершения Action проверьте настоящий Mini App: вход участника и
неподписанного пользователя, доступ двух администраторов, старт classic-1,
открытие каталога и работу опубликованного интерфейса.

## Что действительно проверено

Локально проверены исходное состояние (151 тест) и исправленная сборка (166 тестов),
повторная подготовка, сохранность исходной игры, игрового манифеста и ресурсов.
Отдельно патч наложен на присланный ZIP main с предыдущим CLI-патчем и проверен
повторно. Никакие команды push, migrate или run в живом Telegram здесь не выполнялись.
Зелёные локальные тесты не гарантируют, что сервер примет все прочие параметры.
Точная ошибка этого журнала устранена в конфигурации, которую отправит сборщик.
