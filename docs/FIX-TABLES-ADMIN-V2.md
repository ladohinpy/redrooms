# Исправление запуска + отдельная админка четырёх столов

## Основание и границы диагноза

Исходная копия — предоставленный пользователем `redrooms-main (1)(1).zip`, с последующими исправлениями CLI snapshot и static headers.
Пользовательские скриншоты показывают локальные инструменты старой игры, а не страницу управления релизами.
На сервере ранее был загружен отдельный `admin.html`, но по скриншотам нельзя установить, каким путём пользователь попал в старый экран.
Адрес Main Mini App и отдельной кнопки меню проверяется в BotFather вручную; патч эту настройку не подменяет.

В старом `engine-boot` реально присутствовал небезопасный переход:

```js
if (data.game.id !== engineId || data.game.entry !== location.pathname) {
  navigate(data.game.entry, { release: data.release.id });
  return await new Promise(() => {});
}
```

`/index.html` и `/` — разное написание одного обслуживаемого HTML при канонизации хостом. Старое сравнение способно повторять навигацию,
а вечный Promise не ограничен таймаутом запроса. В тесте точная старая функция воспроизводит этот результат после успешного ответа сервиса.
Новая функция в тех же условиях возвращает каталог и удаляет overlay.
Это не запись сети конкретной пользовательской Telegram-сессии: нельзя категорично утверждать, что только этот сценарий объясняет все её симптомы.

## Изменения

Новый `routes.mjs` сравнивает каноническую форму пути. Навигация имеет ограничение повтора и таймаут. Отдельные этапы вместо одной общей надписи.
Исправленный renderer v07 использует nullable years, нейтральные названия столов и адаптивный интерфейс.
Новая админка — отдельная страница без Three.js, четыре пары «подпись + текст», default-баннер, сохранение/две публикации, копирование и отправка ссылки.
Серверные `saveSimpleSet` / `publishSimpleSet` работают через существующую проверку ID и compare-and-swap всей записи.

Публикация каталога и релиза и, при необходимости, смена default выполняются одной записью. Потеря связи всё ещё означает неизвестный результат:
не следует повторять команду с новым случайным ID до чтения состояния. Конфликт не решается затиранием.
Отправка ссылки проверяет доступ до чтения релиза; получатель исключительно `ctx.initData.user.id`, не пользовательское поле.

## Сохранность

Нет DROP/DELETE/reset миграции. Старый seed не меняется. Оригинальный HTML и old frozen v06/runtime не редактируются.
Известный `classic-1` получает отдельный совместимый runtime v07, но его сохранённая идентичность и ключ прогресса остаются прежними.
Новые наборы используют новую сборку напрямую. Код адаптера ограничен точным известным SHA-256 v06; неизвестные сборки не подменяются.
Полный исторический старый интерфейс остаётся в старом артефакте — эта ветка не делает его входной точкой приложения.

Служебные файлы `tgcloud/lib/rr/config.js` и локальные credentials исключаются из пакета.
Production `rr-prepare --production` заново генерирует конфигурацию только из ваших прежних двух ID.

## Проверки (фактически выполнены)

- 209 Node-тестов, 0 ошибок: прежние 166 + 43 новых.
- Новый набор: разбор списков, строки/точка с запятой/явная запятая, пустые строки, Unicode-дубли, ограничения.
- Атомарная публикация, default, старые каталоги, права обоих администраторов и отказ постороннему, конфликт ревизий.
- Nullable years: отсутствующий год остаётся null; старый несовместимый renderer не принимает такой каталог.
- Повторная навигация: воспроизведение старого зависания и проверка исправленного кода.
- Новый endpoint: отправка только авторизованному вызывающему, отказ для черновика/неадминистратора, скрытие внутренней ошибки Bot API.
- Синтаксический preflight всех JS-модулей и контроль хешей frozen-артефактов.
- 39 отдельных проверок в Chromium, реальная HTML/JS/WebGL сцена с 8 и 201 кассетой, editor на 1280×900/800×600 и 390×844,
  два тестовых администратора, конфликт сохранения, импорт файла, default, ссылка, кнопка запуска, safe-area и положение мобильного управления.

Браузерные тесты офлайн: SDK и Telegram ID тестовые, серверный сервис настоящий по коду, но хранит состояние в памяти локального процесса.
Загрузка ES-модулей идёт через data-обёртку, URL представлен тестовым адаптером. Реальная сетевая навигация WebView, подпись initData,
Telegram API отправки сообщения, native iOS/Android и текущая production-база не проверялись в этой среде.
Политики браузерной среды не изменялись. Для WebGL использовались Xvfb и программный рендерер Chromium.

## Повторить проверки

```bash
node scripts/rr-prepare.cjs
node scripts/rr-check.cjs
DISPLAY=:99 python tests/rr/browser-tables-offline.py
```

Тест `browser-tables-offline.py` сам запускает и останавливает локальный HTTP-сервис на свободном порту, не использует токены и production.
Не переносите `tests` в `public` и не публикуйте тестовый endpoint `/__test_api`.
Скрипт `rr-verify-static.cjs` — отдельный необязательный GET-check хешей публичных файлов; это не замена авторизованному smoke-test.

После публикации: отдельно открыть реальный бот под каждым из двух аккаунтов, проверить default и отдельную ссылку,
проверить отказ третьему аккаунту и доступ к подписке. Живые данные не сбрасывать ради теста.
