# RedRooms — административные проверки вне статистики

Патч поверх `redrooms-main (3).zip` с применёнными `redrooms-admin-entry-access-fix.zip` и `redrooms-attempt-state-fix.zip`. Это не полный проект. Основа — последние исходники и патчи, предоставленные в этом чате; действующий облачный checkout и база не читались.

## Что исправляет

В прежнем серверном коде ID из `RR_ADMIN_IDS` уже получали `mode: preview` без конкурсного слота. Но общий список показывал их в «Всего попыток», а наблюдения запусков учитывали тестеров как аудиторию. Ошибка была в смешении игровых и тестовых показателей, а не в SQL-схеме.

Теперь для двух ID, которые сборка получает из `RR_ADMIN_IDS`:

- Нет лимита в две зачётные попытки. Сервер явно возвращает `attemptLimit: null`, `remaining: null`, `unlimitedAttempts: true`; новые прохождения остаются `preview` без слота.
- Тесты не входят в текущую статистику игроков, предварительный рейтинг, ошибки по кассетам или подсчёт посещений.
- В разделе «Игроки» администраторы по умолчанию скрыты. Фильтр «Показать проверки администраторов» открывает их историю с отдельным числом проверок; «Игровых попыток» у них — 0.
- Ранее сохранённые записи текущих администраторов также исключаются из текущих агрегатов, без удаления или перезаписи.
- Если права позднее сняты, сохранённые записи `preview` не становятся конкурсными результатами.
- Официальные опубликованные итоги и их статистический снимок остаются прежними, даже если позднее участник стал администратором.

История тестовых запусков остаётся в базе и JSON-бэкапах: она нужна для повторной отправки финиша и восстановления начатой игры. Это не расход конкурсной попытки. Нельзя одновременно создавать несколько активных прохождений одного набора: существующая игра продолжается, либо её закрывают без результата. Автоматического удаления потерянного прогресса не добавлено.

## Установка

1. Создать ветку `fix/admin-test-isolation` от актуального `main` с последними исправлениями.
2. Наложить содержимое ZIP в корень репозитория, сохранив папки. Заменить совпадающие файлы, не удалять остальные.
3. Объединить проверенный Pull Request с `main`.
4. Новый запуск **Publish Red Room — Admin & Releases → Run workflow → main → PUBLISH**.
5. Использовать прежние `RR_ADMIN_IDS`, ключ и имя целевого бота. Пустое `admin_ids` использует repository variable `RR_ADMIN_IDS`; заполненное поле запуска имеет приоритет. Новые переменные не нужны.
6. После успешной публикации закрыть и снова открыть Mini App. В «Игроки» оставить выключенным фильтр проверок.

## Приёмка на stage

- Каждый из двух администраторов: пройти активный набор три раза и более. Повторные игры доступны; два конкурсных слота не расходуются.
- После этих тестов число участников и игровых попыток не должно увеличиться. Включение фильтра показывает техническую историю.
- Обычный подписчик: первая и вторая попытки доступны, третья зачётная — нет. Его результаты видны в статистике.
- Сохранённый официальный рейтинг, наборы и JSON-бэкапы не изменены этим исправлением.

## Границы

Схема БД, механизм подписки, allowlist-проверка, код игры, сохранения, стартовый экран и кнопка «Админка» не изменены. Новая игровая сборка не создаётся; существующие frozen-ресурсы не перезаписываются. Штатный бэкап перед публикацией сохранён. Не очищать базу/localStorage и не использовать `--force`.

Патч проверен локально. Реальные аккаунты и сервер Telegram из этой среды не проверялись и не изменялись.
