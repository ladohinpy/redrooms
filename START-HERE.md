# PLAYER UI 1 — публичный экран без административных элементов

Патч поверх опубликованной версии TABLES ADMIN 2. Другие файлы репозитория не удалять.
Подготовлен на основе предоставленного main и ранее выданного tables-admin-v2-патча. На сервере ничего не изменено.

## Что исправлено

Общий `launchFailure` раньше безусловно выводил технический текст и кнопки управления; публичный launcher также содержал постоянную ссылку на админку. Начальные HTML админки показывали служебную шапку ещё до проверки прав.

Теперь обычный неподписанный посетитель видит:

**Игра канала «Витальное кино»**

**Красная комната**

Для входа подпишитесь на канал «Витальное кино» и нажмите «Проверить снова».

**Открыть канал «Витальное кино»** · **Проверить снова**

Нет служебной версии, Telegram ID, этапов, кодов ошибок, кнопок диагностики или управления. Для остальных ошибок используется короткое фиксированное сообщение; исходный ответ сервера не выводится как текст.

`/admin.html` и `/admin-advanced.html` первоначально нейтральны. Только свежий ответ `rrAdminStatus` с точным boolean `isAdmin === true` открывает редактор. Отказ вызывает переход в обычную игру с `rr_default=1`, без страницы «Ваш ID не включён…». Сохранённый в Telegram параметр `admin` не создаёт цикл возврата.

Роль проверяется на сервере как раньше. Удаление кнопок — исправление интерфейса, а не замена защиты API. Список администраторов, ключ, таблица, данные, текущий основной набор, логические версии и сохранения не меняются.

## Установка через GitHub

1. Создать ветку `fix/public-player-ui` от актуального main, содержащего TABLES ADMIN 2.
2. Распаковать этот ZIP. Загрузить его содержимое в корень репозитория с сохранением путей `src/`, `public/`, `config/`, `scripts/`, `tgcloud/`, `tests/`, `docs/`. Не загружать ZIP одним файлом и не создавать лишний уровень вложенности.
3. Сделать Pull Request и объединить с main после проверок.
4. Actions → **Publish Red Room — Admin & Releases** → новый **Run workflow** → `main` → `PUBLISH`.
5. Прежний `TGCLOUD_TOKEN` и прежние два ID в `admin_ids`/`RR_ADMIN_IDS`. Секретов и ID в патче нет. Не делать Re-run старого коммита.
6. После успеха полностью закрыть старое окно Mini App и открыть бота заново. Не удалять таблицу, не сбрасывать данные, не использовать --force.

Адрес Main Mini App остаётся `https://app8804859840.tgcloud.ai/`. Исторические прямые пути `/games/v06/...` или `/games/v07-tables/...` не являются новой точкой входа. Патч сохраняет такие неизменяемые файлы, а для обычного запуска и ссылок на наборы выбирает новый загрузчик.

## Проверка после публикации

- Посторонний неподписанный аккаунт: ровно два действия на экране подписки. Никаких упоминаний управления и служебных обозначений.
- Тот же аккаунт с `?startapp=admin` либо прямым адресом админки: возвращается к обычной игре, с той же проверкой подписки. Шапка редактора и ID не должны даже кратковременно появляться.
- Обычный подписчик: открывается игра, без административной кнопки.
- Павел и Виталий: вход через `https://t.me/vitalkino_stage_bot?startapp=admin`; редактор и сохранение работают. Административная кнопка в игре допускается только для подтверждённых администраторов.
- Ошибка сети/сервера: понятное сообщение и кнопка повтора, без сырых ошибок и диагностики.

## Состав и границы

Новая неизменяемая сборка `v08-player-ui` содержит исправленный клиентский обработчик и прежний игровой код, с уточнением текста о канале. `rrGetLaunch` использует её только для двух точных известных хешей v06/v07. Это не переписывает релизы, каталоги и namespace сохранений. Схема БД, CLI и workflow не изменены.

Адрес канала проверки не меняется: сервер всё ещё настроен на прежний канал (в предоставленном проекте `@redrooms_stage`). В интерфейсе по запросу написано «Витальное кино»; адрес реального канала не угадывался по названию.

238 автоматических тестов пройдены. Дополнительно пройдены 30 новых офлайн-проверок в Chromium (DOM и настоящая WebGL-сцена) и 39 прежних браузерных проверок редактора/публикации/игры с обновлённым ожиданием отказа.
SDK, аккаунты и база в браузерных тестах синтетические/локальные. Переходы браузера проверяются по целевому адресу, а не реальным переходом внутри Telegram. Живые Telegram-аккаунты, native iOS/Android и production-сервер в этой среде не проверены. Перед публикацией патч наложен на отдельную копию исходной сборки и повторно собран.

Отчёты: `docs/PLAYER-UI-TESTS.txt`, `docs/PLAYER-UI-BROWSER.json`. Файлы `tests/` не должны публиковаться в `public/`.
